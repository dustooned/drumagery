# Drumagery

A browser-based playable visual instrument built with Vite, TypeScript, and PixiJS.

GitHub repository:

```text
https://github.com/dustooned/drumagery
```

## Run

```powershell
npm.cmd install
npm.cmd run dev
```

Open:

```text
http://localhost:5173
```

Do not open `index.html` directly. This is a Vite + TypeScript app, so the browser needs Vite to compile `/src/main.ts` into runnable JavaScript. Direct `file:///` loading will not run the TypeScript entrypoint and is also the wrong environment for Web MIDI.

For MIDI testing, use desktop Chrome or Edge. The Codex in-app browser may deny Web MIDI permission. iPad Safari should use touch/debug input because Web MIDI is not required for iPad compatibility.

## Current Controls

- `1-5`: toggle major-key image-sequence loop slots.
- `Q/W/E/R`: trigger burst placeholders.
- Arrow keys: hue and speed.
- `A/S`: distortion.
- `Z/X`: intensity.
- Touch top band: loop toggles.
- Touch lower stage: burst triggers by horizontal zone.
- Touch slide on stage: smooth analog performance control for `hue`, `intensity`, and movement-driven `distortion`.
- Two-finger touch spread on stage: smooth analog `scale` control.
- Debug panel: manual loop, burst, FX, live state, and MIDI calibration readouts.
- Performance Edge Dock: bottom-corner touch overlay for GRID, TV, PLAY, and FX controls while the stage is fullscreen.
- Stage action bar: `Connect MIDI`, `Clear MIDI Learn`, `Kill Loops`, `Reset`, and `Fullscreen`.
- `Hide controls` / `Show controls`: toggles performance mode while keeping touch, keyboard, MIDI, and state updates active.
- `Fullscreen`: opens the drum visual stage as a full-viewport canvas when the browser allows fullscreen requests.
- `Exit`: appears in the stage corner while fullscreen is active and returns to the regular interface.

Fullscreen keeps the internal art coordinate system at 1280 x 720, then scales the Pixi scene to cover the detected canvas size. On screens that are not 16:9, this favors filling the full display over preserving every edge of the 1280 x 720 frame.
- MIDI calibration panel: last 10 messages and learned CC roles.
- `Clear MIDI Learn`: resets learned CC assignments when calibration order is wrong.
- `Kill Loops`: clears active loops and queued bursts without resetting performance controls.

## MIDI Learn Layout

MIDI note roles:
- White-key notes toggle persistent image-sequence loop slots.
- Black-key notes hold procedural Screensaver Nodes, then ease out on release.
- Drum-pad notes trigger short-lived procedural/vector bursts only.

The v1 learn order follows the performance surface layout:
- Knobs 1-8 / analog TV: `hue`, `syncTear`, `phosphorTrail`, `syncBands`, `pixelate`, `distortion`, `bloom`, `intensity`.
- Knobs 9-16 / shape sculpt: `fade`, `density`, `scale`, `burstPower`, `speed`, `verticalRoll`, `chromaShift`, `syncTear`.
- Touch strips/sliders: `verticalRoll`, `chromaShift`.
- Manual extras: `feedback`, `noise`, `contrast`, `chaos`.

Turn knobs 1-8 first, then knobs 9-16, then the vertical-roll and chroma touch sliders. Knob 1 and knob 9 are intentionally mapped to subtler controls so unstable hardware values are less likely to blow up the visual immediately. Arturia MiniLab MkII channel 1 pitch-bend messages (`command 224`, such as `data 0/64`) map directly to `verticalRoll`.

## Performance Controls

The active v1 control set is:
- `intensity`: overall visual force.
- `bloom`: brighter, thicker visual presence without adding a bloom package.
- `distortion`: wobble/glitch amount.
- `syncTear`: analog TV-style horizontal sawtooth tearing.
- `chromaShift`: RGB channel split and color drift.
- `verticalRoll`: old-TV vertical tracking drift and image slip.
- `phosphorTrail`: old-screen persistence, burst ghosts, and loop afterimages.
- `syncBands`: blocky horizontal jump bands and hard sync compression.
- `feedback`: longer visual persistence and slower burst decay.
- `noise`: procedural speckle/noise layer.
- `density`: element count and grid density.
- `contrast`: sharper alpha/brightness separation.
- `chaos`: global instability multiplier for density, distortion, and noise.
- `scale`: size and spatial reach.
- `fade`: persistence/decay feel.
- `hue`: color drift.
- `speed`: animation rate.
- `pixelate`: whole Pixi stage pixelation through a lightweight filter.
- `burstPower`: burst size and force.

MIDI learns unique CCs in the layout order above for the current session.

The active maximum range is expanded to 3x the original max input. Most controls now run from `0` to `3`; `speed` now runs from `0.2` to `6`.

Values above `1` are treated as overdrive. The current overdrive pass increases scanline/noise density, grid intensity, bloom-like line weight, burst force, and whole-stage pixel/sync-tear severity.

To change min/max/default/smoothing values, edit:

```text
src/state/fxConfig.ts
```

To change how strongly each visual reacts to the `0-1` controls, edit:

```text
src/visuals/visualConfig.ts
```

Use `fxConfig.ts` for controller/control levels. Use `visualConfig.ts` for art response intensity.

## Image Sequence Slots

Major-key persistent loops are defined in:

```text
src/visuals/imageSequenceManifest.ts
```

Each slot owns its loop ID, display name, frame list, playback FPS, anchor, scale, and hue offset. Vaporwave, Chrome Tide, Signal Garden, Glass Desert, and Neon Weather currently use the first 24 PNG frames from their folders in `public/sequences`; exported `00024` files are intentionally left unused while the active target stays at 24 frames.

The current v1 layer can render major-key loops as temporal grids. `density` selects 1x1, 2x2, 4x4, 6x6, or 8x8 layouts, `speed` advances frames, `chaos` offsets tile timing, and `distortion` adds simple tile spread/jitter. Mobile/touch-sized screens cap the grid at 6x6. Each major slot owns a `temporalMode`: uniform, cascade, wave, or deterministic randomized.

Each major slot also owns a display blend mode:
- Vaporwave: `screen`
- Chrome Tide: `add`
- Signal Garden: `screen`
- Glass Desert: `multiply`
- Neon Weather: `add`

Black-key screensavers and drum-pad bursts stay separate from the uploaded image-sequence system.

Best master size for scaling is `2560 x 1440`. Export the active image as `wallpaper.webp` when possible, or `wallpaper.png` if the image needs lossless edges. Keep important details away from the outer 8 percent of the frame so it can crop cleanly on different screens.

The current desktop background is loaded from:

Custom start-button sprite drop path:

```text

```

Recommended source size is `224 x 72`, displayed around `112 x 36` CSS pixels. A `112 x 36` 1x source also works.

```text

```

Recommended source size is `64 x 64`.

The Start speech bubble fades in/out over `800ms ease`, auto-closes after 5 seconds, and also closes when Start is clicked again. The taskbar is shown only in the default desktop/debug layout; Big grid and fullscreen hide it.

## Screensaver Nodes

Black-key note holds wake lightweight procedural Screensaver Nodes through state. Held nodes get a sine-like alpha/scale pulse, and releasing the note eases the node out. Drum pads do not own screensaver activation; they remain short burst hits only. The scaffold lives in:

```text
src/visuals/ScreensaverNodeLayer.ts
```

Current node types are `bouncing-shape` and `starfield`. They use seeded procedural drawing, respond to global FX, and do not require uploaded image assets.

## Performance Edge Dock

The Edge Dock lives in:

```text
src/ui/PerformanceEdgeDock.ts
src/ui/performanceDockConfig.ts
```

The overlay uses a safe corner menu and panels for `GRID`, `TV`, `PLAY`, and `FX`. It is mounted inside the visual stage and appears only during stage fullscreen mode, where the main debug panel is not useful. If a dock control changes performance state, a quick `Reset` button appears beside the menu and stays visible across submenus until pressed. It dispatches through `InputRouter` just like the debug panel. The dock container does not block the stage; only visible dock buttons and sliders receive pointer input.

## Architecture Rule

All inputs go through:

```text
Input source -> InputRouter -> StateEngine -> VisualEngine
```

Do not bind visuals directly to MIDI.
